# Getting help

These projects are maintained by one volunteer, so support is best effort. Asking in public helps everyone who has the same question later.

## Before you ask

- Read the project's README and documentation.
- Search existing issues, including closed ones. Your question may already be answered.
- Make sure you're using the latest version.

## Where to ask

| You want to | Do this |
| --- | --- |
| Ask how to use a project | Open an issue with the **Question** form. |
| Report a bug | Open an issue with the **Bug report** form. |
| Suggest a feature or change | Open an issue with the **Feature request** form. |
| Report a documentation problem | Open an issue with the **Documentation** form. |
| Report a security vulnerability | Follow the [security policy](https://github.com/cravingmaker/.github/blob/main/SECURITY.md). Never open a public issue. |
| Raise a conduct concern | Follow the [code of conduct](https://github.com/cravingmaker/.github/blob/main/CODE_OF_CONDUCT.md#reporting-concerns). |

## Asking a good question

- Describe what you're trying to achieve, not just the step that fails.
- Include the version you're using and your environment.
- Share a minimal example: the smallest configuration or code that shows the problem.
- Paste error messages as text rather than screenshots, so they're searchable.

## What to expect

New issues are usually triaged within a week. Help isn't available by email or private message, except for security and conduct reports, and there's no paid support.
